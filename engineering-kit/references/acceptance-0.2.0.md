## 上线后修复清单（低级，排期，不阻塞验收）

1. 引号内的 `gh pr merge` 文字会被误拦（merge 判断从严，在原始文本上匹配）。
2. 空格分隔的长选项值（`--git-dir .git push`）与带引号的完整路径（`"C:\…\git.exe" push`）仍可能识别不到推送；命令替换 `$(git push)` 也未覆盖。
3. `git status` 与 `diff` 的路径未用 `-z`，含 ` -> ` 或末尾空格的文件名有极小的误切分风险。
4. Python 的 `from 包 import 名` 按名字匹配，通用模块名（如 `config`）可能被同名导入误判为有测试。
5. 文件头：带 `r"""`、`u"""` 前缀的文档字符串不被识别；shebang 与 coding 行可凑够字数。
6. 锁只看目录修改时间，没有进程存活检查。
7. 复审记录的 reviewer 与结论由命令行自填，写代码的人可以自己出具报告（已知的设计限制，套件定位是防误操作）。
8. 巡检的“未登记到索引”只检查阶段目录名是否出现在索引文本中，未检查链接是否指向该目录。
9. 项目里的 `testCommand` 与解释器路径需按项目修改（试装用的是原项目 `.venv`，正式接入应在项目内建环境）。

# 经验记录

收工时做经验提炼（工程流程块 R10）之后，怎样把经验记下来。升格为套件能力的走变更集，见技能正文第 4 节。

来源决定处理方式：

- 用户本人提出或采纳的决定、做法：直接记录。
- agent 总结的：只作为候选，列出标题、依据和建议归属，向用户确认后才记录或升格为能力；未采纳的不作为用户经验。

怎样记：

- 只记跨项目可复用的决定、规则和解决问题的方法；项目特有结论仅提炼可迁移的做法。没有可记录的经验时不强行总结。已有条目更新而不重复。
- 记在项目根目录的 `practices/`。需要新建该目录时，要有用户明确的授权记录，普通对话不算持久化授权；Git 仓库把该目录加入 `git rev-parse --git-common-dir` 下的 `info/exclude`，不跟踪、不提交。非 Git 项目直接创建。
- 按主题维护 `product-development.md`、`workflow.md`、`agentic-engineering.md`，以 `README.md` 索引；按实际需要创建。
- 每条记一条可迁移的原则、适用背景、要解决的问题、具体做法、可核实的实际效果和首次出处（项目、日期、例子）。效果未确认就写明，之后在原条目更新；再次验证可补充出处。
- 本轮有新增或更新时，汇报文件和条目；没有则如实说明。

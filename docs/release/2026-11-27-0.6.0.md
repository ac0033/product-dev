# Product Dev 0.6.0 发布记录

## 范围

本次发布插件 0.6.0，内含工程套件 0.10.0；前一版是 v0.5.0（套件 0.9.0）。

- **内容**：v0.5.0 之后合入的 #43：复审轮次收口（可选配置 `modules.review.roundClosure: fix-and-record`），另修了同步 0.5.0 到 dsh-multi-agent-dev 时复审查出的四个套件问题（pre-push 提交范围遇未提交改动、登记锁回收、外部复审产物顺序、pre-push 修后复核范围），以及 #43 两轮复审的全部高、中级问题（登记锁改为 git 引用的比较交换、风险登记按文件串行、收口核对覆盖等）。
- **发布对象**：#43 的合并提交 `c6e42b84e42750c538c5adcc89cd5bf2f619b088`。
- **授权**：同 0.5.0，复审规则专项的功能契约写明每个 PR 合并后发布一版（用户 2026-11-26 确认）；npm 仍由用户登录后发布。

## 回读与验收

- **本地仓库**：`product-dev`、`skills` 的主检出已快进到 origin/main；本专项的工作树、分支（含 Codex 的 T3 工作树）和草稿 PR #40 已清理、关闭。
- **本机插件**：dsh-multi-agent-dev 内置 product-dev 0.6.0，2026-11-27 同步并合入其 main（`95fa7a3`，插件 0.2.4）；同步时的复审又在套件里查出两条高级（轮次收口的设计层面）和几条反复出现的中级，按用户决定另开专项处理，见下面“已知未完成”。
- **隔离环境验收**（2026-11-27 补做，发布后的公开渠道；Claude Code 2.1.322、codex-cli 0.171.0-alpha.13；临时目录用完已删，本机实际的 Claude Code、Codex 配置未动）：
  - Claude Code 全新安装（隔离的 `CLAUDE_CONFIG_DIR`，`claude plugin marketplace add ac0033/skills` 后安装 `product-dev@ac0033-skills`）：得到插件 0.6.0，`gitCommitSha` 为 `c6e42b8`，套件 `VERSION` 0.10.0，含 `gate/review-rounds.mjs`；`tools/stages.mjs --stage A` 能运行并输出环节表。
  - Claude Code 升级：市场用 0.4.1 时的提交 `a189e6f`（本地克隆作市场）装得 0.4.1（套件 0.8.1）；克隆切到当前市场 `9869c85`，`claude plugin marketplace update` 后 `claude plugin update`，输出“updated from 0.4.1 to 0.6.0”，装好的是 0.6.0（`c6e42b8`）、套件 0.10.0，含 `review-rounds.mjs`。
  - Codex 全新安装（隔离的 `CODEX_HOME`，`codex plugin marketplace add ac0033/skills` 后 `codex plugin add`）：得到 0.6.0（ref `v0.6.0`），两份插件清单都是 0.6.0，套件 0.10.0，含 `review-rounds.mjs`。
  - Codex 升级：`codex plugin marketplace add ac0033/skills --ref a189e6f` 装得 0.4.1；去掉隔离配置里市场的 `ref`（相当于跟随当前市场）后 `codex plugin marketplace upgrade ac0033-skills`，`plugin list` 随即显示 0.6.0、缓存里只剩 0.6.0；再 `codex plugin add` 确认，结果不变，套件 0.10.0。
  - npm：从 registry 装 `dsh-product-dev@0.6.0` 到临时目录（`--ignore-scripts`），包版本 0.6.0，内含套件 0.10.0、`gate/review-rounds.mjs` 和 `tools/stages.mjs`；锁文件的 integrity 与上表一致。
- **未验证**：DeepSeek Harness 的 `dsh plugin add`：本机没有 `dsh`，只验证了 npm 包本身的内容；从 0.5.0 升级没单独做，升级路径用的是更早的 0.4.1（跨两个版本）。
